## 接下來要做（依順序）

### 1. 社課照片／成果牆／預告／公告（含行事曆）

**為什麼先做**：社課幾乎每週都有，公告格式又很固定；做好之後，「行事曆」和社課介紹頁的空缺也一起補上。

**現在的做法**：社課負責人在 Discord 發公告，例如：

```
【鐵道社課】
時間：10/12 18:00~20:00
地點：社辦
內容：高鐵與捷運
鐵道社課第三堂課，我們要來認識高鐵與捷運……歡迎對這個主題有興趣的各位來參加！！
------------------------------------------------------------------------
負責人在準備段考，可能ppt做得有點隨便
敬請見諒
建議具備
搭乘過台灣高鐵與台北捷運
參加過前面的社課（《鐵道基本知識》、《台灣鐵道》簡報）
@鐵道社課通知
```

**要做的**：

- **照片和成果牆**
    - 待補
- **每一堂社課一筆資料**：
    - 社課種類（鐵道、聲優…，沿用成果牆的分類）
    - 第幾堂、標題
    - 時間、地點
    - 內容介紹、備註
    - 建議具備：可以連到同一社課前面的堂次
    - Discord 身分組（例如 `@鐵道社課通知`）
- **社課負責人**：每個社課固定指定幾個人（跟排歌組一樣，不一定是幹部），由幹部在後台設定。負責人只能發、改自己社課的公告。
- **一鍵複製 Discord 公告**：照上面的格式產生文字，包含分隔線和 @ 身分組。
- **顯示在網站上**：
    - 社課介紹頁：每個社課顯示「下一堂」與過去的堂次。
    - 首頁公告欄：最近幾天的社課。
    - 行事曆：社課、活動公告、歌謠祭放在同一個月曆。
- **課後**：負責人可以補上簡報連結，學期末就是一份完整的社課紀錄。
- **選做**：社員按「我會來」，讓負責人知道大概人數。

**進度（2026/10/13）**：
- 已完成：每堂社課的資料、社課負責人、一鍵複製 Discord 公告（含預覽）、未公開草稿、課後補簡報、「社課公告」頁、社課介紹彈窗的「下一堂」、首頁公告欄、行事曆。驗證步驟見 [TESTING.md 第 5 節](TESTING.md#5-驗證社課公告與行事曆)。
- 還沒做：照片和成果牆（待補）、「我會來」（列在暫緩）。
- Discord 先做「一鍵複製」，自動發文列在暫緩。

### 2. 點歌系統

歌謠祭最後一塊，側邊欄已經有「點歌系統」的入口。

- 社員點歌，其他人可以 +1；依票數排行。
- 點的歌分成兩種：
    - 歌單裡已經有的：直接對到舊曲。
    - 還沒人剪過的：當成「徵剪輯」清單，給大家報曲時參考（投稿規則寫「點歌清單歡迎作為報曲的參考」）。
- 排歌台挑測試曲、補位時，可以看到哪些舊曲有人點；工作區原本也有「有人點歌」的標記。
- 每人能點的數量要設上限，避免洗版。

### 3. 活動簽到

**背景**：學校的時數系統用 QR code 簽到，那套改不了，也不用改。社團已經有一個掃學生證條碼的簽到 demo（`barcoder`，單一 HTML 檔）：

- 掃學生證背面的 Code 128 條碼取得學號。
- 依場次和簽到時段判斷能不能簽；同一場簽過會擋下。
- 忘記帶學生證可以手動輸入學號。
- 資料存在那台裝置的瀏覽器裡，活動後匯出明細和彙整 CSV。

**要做的**：把 demo 接進網站，變成社團自己的出席紀錄：

- 場次直接用網站上的資料：歌謠祭的上午場、下午一、下午二，或某一堂社課。不用再手動改程式裡的場次設定。
- 簽到紀錄存到網站後端：
    - 多台裝置可以同時掃，資料不會只留在某一台。
    - 網路斷掉時先存在裝置上，連回來再補送。
- 匯出格式維持 demo 的明細與彙整 CSV。
- 學期末可以統計每堂社課、每場歌謠祭的出席人數，之後寫評鑑資料用得到。
- **隱私**：學號只有幹部與該活動的負責人看得到，不公開。

### 4. 招生頁

給期初社大、社團博覽會用的一頁介紹：

- 各社課簡介與近期社課（接第 1 項的資料）
- 近期活動、下一場歌謠祭
- Discord 與粉專連結

可以印成 QR code 貼在攤位上。
