## 0. 準備

照 [README](../README.md) 的「開發環境」把後端和前端跑起來，然後套用最新的資料表：

```
cd NCUACG
venv\Scripts\activate            # macOS / Linux：source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

另開一個終端機跑前端：

```
cd frontend
npm install
npm run dev
```

- 網站：http://localhost:5173
- 後台：http://localhost:8000/admin/ （後台介面是英文，下面寫的按鈕名稱都照畫面上的英文）

> **一個瀏覽器同時只能登入一個帳號**（登入狀態存在瀏覽器裡）。要同時操作兩個帳號，例如「社員甲報曲、社員乙看回報串」，請另開一個**無痕視窗**或換一個瀏覽器。

## 1. 建立帳號

網站帳號就是後台帳號，只有一套。身分分成四種：

| 身分 | 怎麼來的 | 能做什麼 |
| --- | --- | --- |
| 社員 | 網站註冊並驗證信箱，或由超管在後台建立 | 按讚、留言、歌謠祭報曲、回報串閒聊 |
| 排歌組 | 社員被加進某一場歌謠祭的排歌組 | 該場的「管理歌單」頁 |
| 社課負責人 | 社員被指定為某個社課的負責人 | 發、改那個社課的公告 |
| 幹部 | 超管在後台勾選「幹部」 | 登入後台管理社課、活動、歌謠祭；所有場次的「管理歌單」 |
| 超管 | `createsuperuser` 建立 | 全部，包括指定誰是幹部 |

### 1-1 超管（第一次一定要做）

```
cd NCUACG
python manage.py createsuperuser
```

依序輸入 email、名稱、密碼（輸入密碼時畫面不會顯示字，是正常的）。

**預期結果**：用這組 email 和密碼可以登入 http://localhost:8000/admin/ ，也可以登入網站。

### 1-2 社員帳號

有三種方式，**測試時最快的是 B**。

**A. 從網站註冊（想測完整註冊流程時用）**

1. 打開 http://localhost:5173/register ，填好註冊資料後送出。
2. 本機沒有接寄信服務，驗證信會**印在跑 Django 的那個終端機**，長得像這樣：

   ```
   Subject: =?utf-8?b?...?=
   To: someone@example.test

   請點擊此連結完成註冊驗證：
   http://localhost:5173/verify-email?token=一串亂碼
   ```

3. 把 `http://localhost:5173/verify-email?token=...` 整行複製到瀏覽器打開。
4. 到 http://localhost:5173/login 登入（要輸入圖片驗證碼，大小寫不拘）。

**預期結果**：第 3 步顯示驗證成功；沒驗證就登入的話，會顯示「你尚未驗證 email」和「重寄驗證信」按鈕。

**B. 超管在後台直接建立（建一堆測試帳號時用）**

1. 用超管登入後台 →「帳號」→ 右上角「ADD 帳號」。
2. 填 email、名稱、Password、Password confirmation，**勾選「已驗證信箱」**，要當幹部就再勾「幹部」。
3. 按「SAVE」。

**預期結果**：這個帳號馬上可以登入網站，不用收驗證信。

**C. 已經註冊、但找不到驗證信**

後台 →「帳號」→ 打開那個帳號 → 勾選「已驗證信箱」→「SAVE」。

> 測試帳號的 email 建議用 `@example.test` 結尾（例如 `member1@example.test`），這個網域保證不存在，不會寄到別人的信箱。密碼請不要用你在其他網站的真實密碼。

### 1-3 幹部

後台 →「帳號」→ 打開該帳號 → 勾選「幹部」→「SAVE」。

**預期結果**：
- 他用同一組 email、密碼登入 `/admin`，看得到「CLUB」「EVENT」「歌謠祭」，看不到「帳號」（那是超管才能管的）。
- 網站側邊欄「歌謠祭平台」底下出現「管理歌單」，「社課介紹」底下出現「管理社課公告」（幹部可以發所有社課的公告）。

### 1-4 排歌組成員

排歌組是「每一場」分別指定的，新人也可以擔任，不需要是幹部。

1. 後台 →「歌謠祭」→「歌謠祭場次」→ 打開那一場（還沒有的話先看 [3-1](#3-1-建立一場測試用的歌謠祭)）。
2. 拉到最下面「排歌組成員」，選帳號和職位（主排／抄歌／播歌）→「SAVE」。要加更多人就按「Add another 排歌組成員」。

**預期結果**：該帳號重新整理網站後，歌謠祭頁面上方多一個「管理歌單」分頁，只看得到自己負責的場次。

### 1-5 社課負責人

每個社課固定指定幾個人，不需要是幹部。

後台 →「CLUB」→「社課負責人」→「ADD 社課負責人」→ 選社課與帳號 →「SAVE」。同一個人可以負責好幾個社課，就加好幾筆。

**預期結果**：該帳號重新整理網站後，側邊欄「社課介紹」底下出現「管理社課公告」，只能發、改自己負責的社課。

### 建議準備的測試帳號

| 帳號 | 建立方式 | 用途 |
| --- | --- | --- |
| 超管 | 1-1 | 後台設定 |
| 社員甲 `member1@example.test` | 1-2 B | 報曲、繳交 |
| 社員乙 `member2@example.test` | 1-2 B | 撞曲、回報串留言 |
| 排歌組 `staff1@example.test` | 1-2 B ＋ 1-4 | 管理歌單（**不要**勾幹部，才能確認非幹部的排歌組也能用） |
| 鐵道社課負責人 `lead1@example.test` | 1-2 B ＋ 1-5（社課選「鐵道」） | 社課公告（同樣**不要**勾幹部） |

## 2. 驗證歌謠祭：舊曲清單、歷屆歌單

### 2-1 匯入試算表

1. 到 Google 試算表「中央動畫社線上歌單」和「最新播放曲目統計」，各自選「檔案 → 下載 → Microsoft Excel (.xlsx)」。
2. 後台 →「歌謠祭」→「舊曲（歌單）」→ 右上角「匯入試算表」，兩個檔案都選，按「試跑」。
3. 確認數字沒問題後，再選一次檔案，按「匯入」。
4. 再按一次「試跑」。

**預期結果**：
- 第 2 步顯示「舊曲：新增 2492…」「播放紀錄：58 場…」（數字以當時的試算表為準），最後一行是「（試跑：以上變更都沒有寫入）」。
- 第 4 步顯示「新增 0、更新 0、沒有變動 2492」：重複匯入不會多出資料。
- 「舊曲」「播放紀錄」在後台只能看、不能改（沒有新增、儲存按鈕）。

### 2-2 公開頁面（不用登入）

| 網址 | 操作 | 預期結果 |
| --- | --- | --- |
| /songfest | 打開 | 「最常播的歌」有排行；可以切換「近 4 年／全部」 |
| /songfest/library | 搜尋 `ＲＡＩＬＧＵＮ`（全形） | 找得到 D2902 only my railgun（全形半形、大小寫都不影響） |
| /songfest/library | 點「か行」 | 只剩か行的歌，網址多了 `group=か` |
| /songfest/library | 排序改「近 4 年最常播」 | 最上面是播最多次的歌 |
| /songfest/setlists | 點「114下期末」 | 列出 85 首，結尾的 5 秒畫面影片有黃色底 |

### 2-3 跟排歌組的試算表對資料

挑幾首歌，比對網站「播放」欄（格式是「近 4 年／全部」）和「上次播放」，跟排歌組工作區試算表的「4年內播放次數」「上次播放」是否一樣。

已知會不一樣的情況：試算表只用**曲名**去找，所以同名但不同首的歌（例如 NARUTO 和狼與辛香料都有〈Sign〉）會被試算表算在一起；網站用「歌曲出處 + 曲名」，分得出來。

## 3. 驗證歌謠祭：新曲投稿

### 3-1 建立一場測試用的歌謠祭

後台 →「歌謠祭場次」→「ADD 歌謠祭場次」：

> 時間欄位分成日期和時間兩格，旁邊的「Today」「Now」可以快速填今天、現在。

| 欄位 | 填什麼 |
| --- | --- |
| 名稱 | `測試場` |
| 日期 | 今天之後的任一天 |
| 形式 | 大講堂（排歌單） |
| 報曲截止 | 3 天後 |
| 窗歌截止 | 5 天後 |
| 新曲與 5 秒畫面繳交截止 | 7 天後 |
| 合作社團新曲上限 | `1`（方便測上限） |
| 出曲規定 | 隨便打幾行字 |
| 亂入曲截止、表單網址、說明 | 隨便填 |
| 排歌組成員 | 加入 `staff1`，職位「主排」 |

> 網站會把「**今天以後最近的一場大講堂歌謠祭**」當成目前的場次。如果資料庫裡還有其他未來的場次，請把測試場的日期設得比它們早。
>
> 後台的時間都是台灣時間。

**預期結果**：網站「新曲投稿」與「亂入投稿」頁顯示這一場和各項截止時間。

### 3-2 報曲（社員甲）

後面的步驟會用到社員甲的 4 首歌，這裡先一次報好：

| 代號 | 曲名 | 後面拿來測 |
| --- | --- | --- |
| A | `星座になれたら`（歌曲出處、畫面出處都填 `ぼっち・ざ・ろっく！`，勾「要上傳 5 秒畫面」） | 撞曲、繳交、閒聊 |
| B | 隨意 | 窗歌與罰則 |
| C | 隨意 | 逾期未繳交與延期 |
| D | 隨意 | 刪除 |

1. 社員甲登入 → 歌謠祭 →「新曲投稿」→「＋ 報曲」。
2. 填歌曲出處、畫面出處、曲名、歌曲連結（畫面或作品屬性可以不填）→ 送出。4 首都照做。

**預期結果**：「我的投稿」出現 4 首，狀態都是「已報曲」，製作者是社員甲的名稱。

### 3-3 撞曲（社員乙，用無痕視窗）

1. 社員乙報 A 那首：歌曲出處 `ぼっち・ざ・ろっく！`、曲名 `星座になれたら`（也可以試試前後加空白）。
2. 再報一首曲名相同、但歌曲出處不同的歌。

**預期結果**：
- 第 1 步被擋下，訊息寫出是社員甲報的。
- 第 2 步可以送出（同名但不同首）。

### 3-4 修改、刪除（報曲截止前）

社員甲在 B 按「修改／繳交」改曲名 → 儲存；再把 D「刪除」。

**預期結果**：兩個操作都成功，刪除不會有罰則。

### 3-5 繳交

1. 社員甲在 A 按「修改／繳交」，「檔案連結」填任意網址、「影片長度」填 `4:25` → 儲存。
2. 先讓排歌組在「管理歌單」勾 A 的「檔案已確認」，社員甲再編輯一次，把長度改成 `4:30` → 儲存。
3. 在 C 試試只填檔案連結、不填長度。
4. （選做）在 A 的「連曲」選 B → 儲存，A 的卡片會顯示「連曲〈B〉」。兩首都填了長度、合計超過 10 分鐘時，排歌組那邊會出現提醒。

**預期結果**：
- 第 1 步後狀態變「已繳交」，長度顯示 4:25。
- 第 2 步後，排歌組的「管理歌單」在這首旁邊出現「繳交後改過檔案或長度」的提醒，「檔案已確認」被取消勾選。
- 第 3 步顯示「繳交時請填影片長度」，C 維持「已報曲」。

### 3-6 回報串與閒聊

1. 社員乙切到「回報串」分頁，在社員甲的 A 按「閒聊」，留一句話。
2. 社員甲重新整理，打開同一首的閒聊。
3. 排歌組帳號打開同一首的閒聊。

**預期結果**：
- 回報串看得到社內與合作社團的投稿，**看不到亂入曲**。
- 社員甲看得到留言、閒聊數變成 1，但不能刪社員乙的留言（沒有刪除按鈕）。
- 排歌組可以刪除任何人的留言。

### 3-7 合作社團上限

社員乙報曲時「投稿身分」選「健行科大」報一首，再用同樣身分報第二首。

**預期結果**：第二首被擋下，訊息是「健行科大的新曲已經滿 1 首」。

### 3-8 報曲截止後

後台把「報曲截止」改成**過去**的時間（例如昨天）→「SAVE」。

**預期結果**：
- 截止時間旁邊標「已截止」，「＋ 報曲」按鈕消失。
- 社員甲的投稿：「刪除」變成「窗歌」；按鈕變成「繳交／修改說明」，歌曲欄位反灰不能改。

### 3-9 窗歌與罰則

1. 後台把「窗歌截止」也改成過去的時間。
2. 社員甲在 B 按「窗歌（會記罰則）」→ 確認。
3. 後台把「測試場」的日期改成**昨天**，再新增一場「測試場2」：日期在未來、報曲截止在未來。
4. 社員甲打開「新曲投稿」。
5. **用超管或幹部帳號**到「管理歌單」，場次選「測試場」，點 B 的歌名 → 勾「免除罰則」。
   （`staff1` 只負責「測試場」，那一場變成過去之後，他的「管理歌單」會消失，這是正常的。）
6. 社員甲重新整理。

**預期結果**：
- 第 2 步跳出提醒「現在窗歌會被記罰則」，窗歌後狀態變「窗歌」。
- 第 4 步顯示「你在 測試場 的〈…〉逾期窗歌，依規定這次不能報曲」，沒有「＋ 報曲」按鈕。
- 第 6 步可以報曲了。

### 3-10 逾期未繳交與延期

1. 後台把「測試場」的日期改回未來，並刪掉「測試場2」。
2. 後台把「新曲與 5 秒畫面繳交截止」改成過去的時間。
3. 排歌組在「管理歌單」點 C 的歌名 →「延後繳交到」選明天 →「儲存延期」。
4. 社員甲重新整理，繳交 C。

**預期結果**：
- 第 2 步後 C 狀態變「逾期未繳交」，排歌組那邊這首標「罰則」；有勾 5 秒畫面的話，5 秒畫面變「取消」。
- 第 3 步後狀態變回「已報曲」，社員甲看到「繳交截止（已延期）」。
- 第 4 步可以繳交。

### 3-11 排歌組總覽

用 `staff1` 登入 → 歌謠祭 →「管理歌單」：

| 操作 | 預期結果 |
| --- | --- |
| 看上方統計 | 新曲數、已繳交、5 秒畫面、新曲總長都跟下面的列表對得起來 |
| 在亂入曲或沒長度的歌填長度 `3:30`，點別的地方 | 「新曲總長」跟著增加 |
| 勾某首已繳交歌的「檔案已確認」 | 重新整理後還是勾著 |
| 點歌名 →「退件」→ 輸入原因 | 狀態變「退件」；投稿者在「我的投稿」看到退件原因；回報串只有投稿者本人看得到 |
| 篩選「未繳交」「有提醒」、來源「亂入」 | 列表只剩符合的 |
| 「匯出 CSV」 | 下載的檔案用 Excel 打開中文正常，欄位順序跟原本的「新曲」工作表一樣 |
| 「複製催繳名單」 | 剪貼簿裡有依製作者整理的未繳名單（瀏覽器不允許複製時，會改成顯示文字框） |
| 用社員帳號直接開 /songfest/manage | 顯示「這一頁給排歌組使用」 |

### 3-12 匯入亂入曲

1. 到亂入曲的 Google 表單 →「回覆」→ 綠色試算表圖示開啟回覆試算表 →「檔案 → 下載 → Microsoft Excel (.xlsx)」。
2. 「管理歌單」→「匯入亂入曲表單」→ 選剛下載的檔案。
3. 同一個檔案再匯入一次。

**預期結果**：
- 第 2 步顯示「亂入曲：新增 N 首」，列表多出來源「亂入」的歌，有附檔案的狀態是「已繳交」。
- 第 3 步顯示「新增 0 首、更新 N 首」，不會重複；排歌組填過的長度不會被蓋掉。
- 點亂入曲的歌名看得到投稿人信箱；社員在回報串看不到亂入曲。
- 跟社內投稿撞曲、上一場播過、超過亂入截止才投稿的，會出現對應的提醒。

> 表單回覆含投稿人的 email，只能在本機或正式站匯入，**不要放進 repo**。

### 3-13 側邊欄與分頁

| 帳號 | 預期結果 |
| --- | --- |
| 沒登入 | 側邊欄「歌謠祭平台」看得到舊曲清單、新曲投稿、亂入投稿說明/投票、歌單瀏覽；「新曲投稿」頁提示要登入 |
| 社員 | 多了「點歌系統」（還在建置中），沒有「管理歌單」 |
| 排歌組（非幹部） | 多了「管理歌單」 |
| 幹部 | 有「管理歌單」，場次選單看得到所有未來與有投稿的場次 |

## 4. 驗證歌謠祭：排歌台與活動後

先用 `seed_songfest_demo` 建好投稿（見 [常見問題](#常見問題)），再用排歌組帳號到「管理歌單」→「排歌」。

| 操作 | 預期結果 |
| --- | --- |
| 第一次打開「排歌」 | 自動建立測試曲、上午場、下午一、下午二；目標長度分別是輪播 2 輪、1:58、1:48、1:58（下午二含結尾影片） |
| 「一鍵初排」 | 左邊「還沒排的新曲」清空（備曲除外）；同一人的歌分散在不同場；連曲兩首排在一起 |
| 在上午場搜尋 `おたキング` 加入 | 出現 D0713，標「上一場播過」（114下期末有播） |
| 「加入 CM」，長度 5:30 | 放在上午場第 1 首，後面每首的「播完」時刻往後移 |
| 把某首往上、往下、移到別的時段，或直接拖拉（桌機） | 順序立即更新，兩個時段的編號都重新排 |
| 用「其他」加一首長度 2:00:00 的項目到已經有歌的上午場 | 總長變紅，提醒「要提早到 幾點幾分 開播才能在 12:00 結束」 |
| 把一首新曲在「管理歌單 → 投稿總覽」退件，再回到排歌 | 那首被劃掉、標「已窗歌或退件」；按「找舊曲補位」選一首，換成長度接近的舊曲 |
| 熱度填數字 | 重新整理後還在；不填也可以 |
| 「時段設定」改開播時間 | 講話、預計結束、最晚結束一起變 |
| 四個匯出按鈕 | 對外公開歌單（CSV）、排歌工作區（CSV）、播放順序（新曲用投稿規則的檔名格式）、結尾名單（剪輯、亂入、特別感謝合作社團、5 秒畫面段數） |
| 勾「公布到歌單瀏覽」 | 沒登入也能在「歌單瀏覽」看到這一場，依時段列出；窗掉的歌不會出現 |

活動後（「管理歌單」→「活動後」）：

| 操作 | 預期結果 |
| --- | --- |
| 「寫入播放紀錄」 | 這場的播放紀錄換成排好的歌單（CM 和窗掉的不算，結尾影片記成「5秒畫面」）；舊曲的上次播放跟著更新 |
| 把場次日期改成今天以前，投稿者打開「新曲投稿」 | 出現「入歌單回報」，可以勾同意 |
| 排歌組勾選同意的新曲 →「自動編號並收進舊曲」 | 接著目前最大的 DVD 編號往下編（每片 20 首），舊曲清單搜得到 |

> 寫入播放紀錄和收進歌單會改到正式資料，測試時請用測試場次，測完記得清掉（見第 7 節）。

## 6. 自動測試

```
cd NCUACG
python manage.py test accounts club event songfest
python manage.py makemigrations --check --dry-run

cd ../frontend
npm run lint
npm run build
```

**預期結果**：後端顯示 `OK`；`makemigrations` 顯示 `No changes detected`；前端兩個指令都沒有錯誤。

歌謠祭的投稿規則照「歌謠祭曲目投稿規則」逐條寫成測試，在 `NCUACG/songfest/tests_submissions.py`。規則有改時，請一起改測試。

## 7. 測完清理

**只刪測試資料**：
- 後台 →「歌謠祭場次」→ 勾「測試場」「測試場2」→ 上方 Action 選「Delete selected 歌謠祭場次」→「Go」→ 確認。底下的投稿、留言、排歌組會一起刪掉。
- 後台 →「CLUB」→「社課堂次」→ 勾測試用的堂次 → 用同樣的方式刪除（也可以在網站的「管理社課公告」按「刪除」）。
- 測試照片在網站的相簿點開照片按「刪除」（檔案會一起刪掉）；後台 →「CLUB」→「照片」也可以刪。
- 測試作品在「管理成果牆」按「刪除」。
- 後台 →「帳號」→ 勾測試帳號 → 用同樣的方式刪除。

**整個資料庫重來**：

```
cd NCUACG
del db.sqlite3                    # macOS / Linux：rm db.sqlite3
python manage.py migrate
python manage.py createsuperuser
```

之後再照 [2-1](#2-1-匯入試算表) 匯入試算表。`db.sqlite3` 不會進 repo，刪掉只影響你自己的電腦。

## 常見問題

**看不到「管理歌單」**
- 要是幹部，或是**今天以後**某一場歌謠祭的排歌組成員。
- 身分是登入時讀取的，被加進排歌組後請重新整理頁面。

**看不到「管理社課公告」**
- 要是幹部，或是後台「社課負責人」裡有這個帳號。身分是登入時讀取的，請重新整理頁面。

**`runserver` 說 8000 port 不能用**
- Windows 有時會把 8000 附近的 port 保留給系統。改用 `python manage.py runserver 8100`，前端用 `BACKEND_URL=http://localhost:8100 npm run dev` 啟動，後台網址也跟著變成 http://localhost:8100/admin/ 。

**「新曲投稿」顯示「目前沒有準備中的歌謠祭」**
- 要有一場「形式：大講堂」、「公開」打勾、日期在今天以後的歌謠祭。

**顯示「這一場還沒開放投稿」**
- 那一場沒有填「報曲截止」。

**「上一場播過」「罰則」看起來不對**
- 這兩項都以「上一場大講堂歌謠祭」為準。播放紀錄要匯入到最新一場，否則會拿更早的場次來比。

**從「管理歌單」點「Django 後台」打不開**
- 開發時後台在 http://localhost:8000/admin/ ，請確認 Django 有在跑。正式站前後端不同網域時，要在 `frontend/.env` 設 `VITE_ADMIN_URL`。

**想快速建一堆投稿來測**
- `python manage.py seed_songfest_demo --staff 排歌組的email --members 社員的email`，會在目前的場次建好各種狀況的投稿，可以重複執行。

**終端機的驗證信中文變成亂碼**
- 不影響驗證，只要複製 `http://localhost:5173/verify-email?token=...` 那一行就好。
